## Working rules for every lane

1. `git worktree add -b lane/<name> ../bdf-<name> master`, then work **only** there; a target
   directory belongs to one tree (`CARGO_TARGET_DIR=$HOME/target-bdf-<name>`).
2. TDD: failing test first, observed failing.
3. `bash scripts/wsl-build.sh` (the whole gate) before every commit. Never commit red.
4. Commit trailers per AGENTS.md rule 9; a new dependency needs a `docs/DEPS.md` row in the
   same commit and `cargo deny check` green.
5. Never touch `corpus/raw/private/` (real customer documents) and never run
   `scripts/publish-public.sh`. Push the lane's own branch at most.
6. Report the commit SHA, the exact gate tail, and the raw output backing every claim. A lane's
   summary is a claim; the orchestrator re-runs the check before integrating.

## What today's evidence settles (2026-09-29, after three instruments)

* **The allow-list is doing real work and, at document level, doing it correctly.** The 14
  files ordered by `producer_visual_order_known` all emit text that scores as **logical**
  against poppler's `-layout` reading (0.78–0.92 vs 0.33–0.58 for the reversal — decisive
  margins). Inverting them was the right action, so the entries that caused it are
  evidence-backed: Microsoft Word (LTSC, 2013, 2021, 2024) and Adobe PDF Library
  (16.0.7, 17.0). Caveat: the check scores whole documents; a per-page version is stronger.
* **The earlier alarm was void.** Two research instruments said the allow-list was inverting
  logical files and that "all 14 refusals store logical order". Both could not discriminate
  (`docs/problems/0011`); neither claim is used anywhere.
* **The refused 14 come from producers with no evidence at all** — `Microsoft: Print To PDF`,
  `Microsoft® Excel®` (LTSC/2016), Foxit Reader PDF Printer, cairo, ReportLab PDF Library,
  Adobe Acrobat Pro 11, one with no `/Producer`, two pypdf cannot open. Adding any of them to
  the allow-list requires **rendered pixels read by an eye** (AGENTS.md rule 8), not an
  instrument, because a wrong entry here reverses text silently.
* **The preferred fix for the refused files stays measurement**: a faithful per-character
  prediction (phase 2b) decides a line by reproducing its painting, which needs no answer key
  and no producer convention.

## Lane A (dispatched 2026-09-29)

Font-aware character recovery for fonts whose `/ToUnicode` is absent or unusable — see the
dispatch brief; target `hebrew-1.pdf` (29 pp, 9 fonts, **0 `/ToUnicode`**, `/Identity-H`, no
`/CIDToGIDMap`), whose Hebrew titles currently decode to Sinhala/Malayalam garbage.
Outcome: **blocked** — 10 tool calls and 87 s of reconnaissance only (worktree and branch
`lane/w16-font-recovery` created, no implementation, no commit). Leaf lanes on this runtime run
a small model with a short budget, so deep work is the orchestrator's; lanes are for mechanical,
precisely-specified chores. Also measured, and the reason phase 1a exists: the CLI emits
**47,897 characters** for `hebrew-1.pdf` while reporting `ok:false` with all 29 pages false.

## Owner decisions (asked and answered, 2026-09-29)

1. **Order of work:** font track first — 1a (stop emitting broken-decode text), then 1b
   (recover identity from the font program), then the order work (2a/2b/2c).
2. **Withholding granularity:** **per font** — a page keeps the text of fonts that decoded
   correctly and withholds only the broken fonts' text.
3. **Authority while the owner is away:** changes to what callers receive may be decided by the
   orchestrator, with the archive delta reported and the old behaviour revertible.
4. **The refused 14:** **measurement only** — the allow-list stays a last resort and an entry
   requires a rendered page read by an eye. A loud refusal is an acceptable answer.
5. **Hygiene:** dispatch lane C for the mechanical chores.
