# Canary plan — the first version someone else can run

Decided by the owner, 2026-10-03. This supersedes the phase list in `docs/ROADMAP.md` for
anything that is not needed to hand a working binary to a reader.

## What a canary is

A single static Linux x86_64 binary that extracts text from real RTL PDFs and is **honest about
what it cannot prove**: every page is either returned in logical order or refused with an explicit
reason. No writing, no editing, no MCP, no GUI, no OCR.

## The four owner decisions that shape it

| Decision | Answer | Consequence |
|---|---|---|
| Scope | Extraction-only CLI | W4 (writer), W5 (editing), W8 (MCP, packaging, enterprise) are **out of the canary**. |
| Licence | No licence file; all rights reserved, shared by invitation | The repo gets an explicit `License: TBD — all rights reserved` marker. Do **not** add a LICENSE file, and do not describe the project as AGPL in the canary materials: AGPL is a *planned* posture (`docs/decisions/0001`), not the licence of the canary. |
| Platform | Linux x86_64, single static binary | Build with `x86_64-unknown-linux-musl` so the binary has no runtime dependency. |
| Human review | The owner reads rendered pages | No canary claim about text correctness ships without a human read of a rendered page. This is the existing rule (`AGENTS.md` rule 8), and it is the only oracle for RTL order. |

## Tasks, in order

### C1 — Per-font withholding (phase 1a)
**Why:** a page may mix a font that decodes with a font that does not. The readable text must
survive; the unreadable text must be withheld and named.
**Done when:** a two-font fixture (one good `/ToUnicode`, one broken) exists as a committed
generator, and a RED test states the expected behaviour — good-font text present, broken-font text
absent, `ok:false`, reason present. Then implement only if the test is genuinely red.
**Note:** reading the code suggests this may already hold (`recover.rs:1738` leaves a CID font with
broken `/ToUnicode` out of the map, and `show()`'s `None` arm sets `undecodable` without emitting).
The test decides; do not implement to match this note.

### C2 — Font-program recovery: CLOSED as a refusal, no code needed
**Why it was planned:** `hebrew-1.pdf` was believed to emit 47,897 characters of wrong-script
text needing cmap inversion. **Measured 2026-10-03: that was false.** It is an English/Spanish
volume; all 29 pages emit readable text via `/Encoding` (`encoding_mapped`), and every page
correctly reports `ok:false` + `unsupported_broken_to_unicode` for the Hebrew runs.
Its four fonts carry **no embedded program at all**, so there is nothing to invert — the
planned recovery cannot apply to this file.
**Done when:** satisfied by measurement. Record: `docs/problems/0013`.
**Re-target rule:** only attempt recovery for a font that *embeds a program* and lacks a
usable `/ToUnicode`. Assert that first; "no `/FontFile*`" means refuse, never guess.

**Also checked so it is not re-checked:** `al-bdf-engine` does not do this either — it only
writes `/ToUnicode`; its `P4` failure for broken maps was fixed by sanitising characters so
the file opens. Nothing to port.

### C3 — Order recovery that decides (phase 2b, then 2c)
**Why:** 14 of 51 real files refuse because the geometry ties and nothing else can decide.

**Measured 2026-10-03 — where the refusals actually come from.** The rung refuses at
`recover.rs:473-478`: any line where two units share a `paint_x` is `Ambiguous`. The cause is
that every unit takes its position from the text origin, so clusters painted at one origin all
tie. The pen model (`Metrics`, declared widths ÷1000, advanced in text space and projected once)
is what breaks the tie — **and 11 of the 14 refusing files do declare widths**:

| file | fonts | Type0 | declare `/W` |
|---|---|---|---|
| arabic-3, persian-1/2/3, persian-panel1, persian-payvast1-2 | 2–6 | all | **yes** |
| persian-4, persian-6, persian-report-noc-revision, unknown-resume-devops-1 | 4–12 | 5 of 9–12 | **yes** |
| english-1, he-eng-ar, persian-hld-7-summary-fa | 3–6 | 0 | **no** |

So the work splits: **11 files are winnable** by making the prediction faithful, and **3 are not** —
a file that declares no widths leaves every cluster at one origin, so its order is genuinely
unanswerable from geometry. Those 3 must keep refusing unless a different rung (a producer
fingerprint verified by a rendered page) can decide them.

**The faithfulness problem, located.** `painted_map` (line 516) runs UAX #9 over a **proxy string**
in which every unit is collapsed to ONE character (`proxy_char(&units[i].text)`, line 508). A unit
holding several characters — a ligature, or a mixed run — loses its internal structure, and a mixed
line's predicted painting is exactly where that matters. `predicts_painted` therefore compares
against a prediction that cannot represent the hypothesis it is testing.

**Done when:** the prediction is faithful per character, and only then is the consistency check
relaxed — in that order. Acceptance: the 11 winnable files emit, and their output reads correctly
to the owner. The 3 widthless files are expected to keep refusing; a refusal there is correct, not
a failure.
**Never:** loosen a comparison before the prediction it is compared against is faithful. Relaxing
the tie rule without fixing the proxy is what caused the `hebrew-4.pdf` silent reversal
(`docs/problems/0009`), which is why that attempt was withdrawn.

### C4 — Static Linux binary
**Why:** a canary someone can run is a canary they can download.
**Done when:** `x86_64-unknown-linux-musl` builds clean, the binary is static (`ldd` says "not a
dynamic executable"), it passes the contract tests, and its output on the public fixtures is
byte-identical to the glibc build.
**Needs the owner:** where the binary is hosted, and who receives it.

### C5 — Canary documentation
**Done when:** a `CANARY.md` states what the binary does, what it refuses, the exit codes, the
known limitations (private-corpus refusals, OCR out of scope, order unproven on some files), and
the invitation-only licence position. Claims about correctness cite the numbers and name who read
the rendered pages.

### C6 — Licence and invitation markers
**Done when:** `README.md` and the repo metadata carry `License: TBD — all rights reserved`, and
nothing in the published tree claims AGPL for the canary build.

### C7 — Final review with the owner
**Done when:** you have run the binary yourself on a real PDF, read at least three rendered pages,
and confirmed the output. This is the gate that no automated check can substitute for.

## Explicitly not in the canary

Generation/writer · editing · redaction · forms · signatures · encryption · OCR · MCP server ·
multi-platform packaging · PDF/A and PDF/UA conformance · the final licence decision.

## What "done" means for the canary

A named person clones nothing, downloads one static binary, runs
`pdfrtl extract --json <file.pdf>`, and gets either correct logical text or a clear refusal — and
can tell the difference.
