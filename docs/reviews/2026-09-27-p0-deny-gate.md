## Two real defects the gate caught (before any product code existed)

Both were in the skeleton itself — recorded because they are exactly the class of mistake
that would otherwise surface months later, inside a dependency update.

| # | Gate | Error | Root cause | Fix |
|---|---|---|---|---|
| 1 | `bans` (wildcard) | `found 1 wildcard dependency for crate 'pdfrtl-cli'` / `'pdfrtl-mcp'` | intra-workspace deps were `{ path = "…" }` with no `version`, i.e. an implicit `*` requirement | `{ path = "../pdfrtl-core", version = "0.0.1" }` in both crates |
| 2 | `licenses` | `failed to satisfy license requirements` ×3 | our own crates are `AGPL-3.0-or-later` **by design** (ADR 0001) but are not, and must not be, in the permissive allow list | `[licenses.private] ignore = true` — applies only to unpublished workspace crates, so a third-party crate can never inherit the exemption |

Also removed a speculative `[[licenses.exceptions]]` block for `freetype-sys` — YAGNI: that
crate is not in the graph, and an unused exception is a config lie.

## Why `clippy -D warnings` earned its place (first draft)

The first draft of `crates/pdfrtl-cli/src/main.rs` declared `EXIT_UNSUPPORTED` with no user,
because the unsupported path arrives in P1. Clippy failed the build on dead code. The fix
was not `#[allow(dead_code)]`: the exit-code contract moved into
`crates/pdfrtl-cli/src/exit.rs` as **public API**, where a public constant is by definition
not dead, and where an integration test pins all three values. The invariant's exit code now
exists as a tested contract before the code path that uses it.
